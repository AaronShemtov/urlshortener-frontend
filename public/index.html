How it works

Two HTTP endpoints, one per concern. The same backend image runs in two modes — writer and reader — selected by an environment variable.

POST /shorten

Random 6-character base62 code generated server-side. Writer pod inserts the document into the Autonomous JSON Database via SODA REST PUT. Returns the short URL.

POST /createcustom

Custom slug provided by the caller. Writer pod validates the slug, checks for collision, then inserts. Returns 409 Conflict if the slug is taken.

GET /{code}

Reader pod fetches the document by code and returns an HTTP 301 redirect. Reader scales independently of writer — most real-world shortener traffic is reads.

$ curl -X POST https://1ms.my/shorten \ -H "Content-Type: application/json" \ -d '{"url":"https://docs.kubernetes.io/some/long/path"}' # {"short_url":"https://1ms.my/abc123","code":"abc123"}

Behind the scenes

This shortener is the live application on the platform documented at infra.1ms.my. It is built, tested and deployed via GitOps — every change starts as a Git commit.

Stack

  • Backend — Go service, distroless image (~12 MB). Standard library only; no Oracle client libraries.writer/reader split via MODE env var · 2 replicas
  • Storage — Oracle Autonomous JSON Database accessed via SODA REST.basic auth over HTTPS · same region
  • Frontend — this page: static HTML + JS, served by nginx-unprivileged.no framework · no build step
  • Ingress — Cloudflare Tunnel → Envoy Gateway → HTTPRoute → Service.no public cluster IP · zero inbound ports

Operations

  • Build — GitHub Actions run on every push to main.linux/arm64 multi-tag · semver + sha
  • Promote — Flux Image Automation watches OCIR and updates manifests.commits tag updates back to personal-k8s
  • Deploy — kustomize-controller applies manifests; rolling update follows.~3 minutes from push to running pod
  • Secrets — External Secrets Operator syncs ADB password from OCI Vault.no static credentials · instance principal auth
